Si integras RQE como **plataforma para tus propios clientes** (patrón partner/reseller), estos endpoints te dejan **crear y configurar un proyecto-cliente completo por API**: su dominio de envío con el pack DNS, su remitente, su API key y su webhook. Todo con tu partner-key, sin pedirle nada a la key del cliente.

**Base URL:** `https://api.reallyquickemails.com`

<Info>
  **Cada cliente = un proyecto.** El dominio, el reply domain, los límites y las estadísticas son **por proyecto**, así que cada cliente tuyo es un proyecto RQE independiente con su propia API key. Estos endpoints crean, configuran y listan esos proyectos dentro de **tu** organización de partner.
</Info>

## Autenticación

Los endpoints de partner usan una **partner-key** dedicada (distinta de las API keys de proyecto):

```
Authorization: Bearer sk_partner_xxxxxxxxxxxx
```

La partner-key está asociada a tu organización y solo puede operar proyectos **dentro de ella**. Es dedicada y revocable sin afectar tus envíos. Se emite desde RQE al habilitar tu cuenta de partner. Una key ausente o inválida responde `401`. Un `projectId` que no pertenece a tu organización responde `404`, nunca `403`: desde afuera, un proyecto ajeno es indistinguible de uno que no existe.

<Warning>
  **La partner-key no envía correo.** Sirve para provisionar y configurar. Para enviar, gestionar contactos o consultar actividad de un cliente, usa la `api_key` (`sk_proj_...`) de su proyecto.
</Warning>

## Alta completa en una llamada

Es el camino recomendado. Un solo `POST` crea el proyecto, registra el dominio de envío con el pack DNS completo y deja el remitente creado sobre ese dominio.

<Steps>
  <Step title="Crea el cliente entero">
    `POST /v1/partner/projects` con `name`, `domain` y `sender`. Recibes `project_id`, `slug`, la `api_key` del cliente, los registros DNS y el link público de verificación.
  </Step>
  <Step title="Reenvía el link de verificación">
    `domain.verification_url` es una página pública que muestra los registros y verifica con un botón. La abre el cliente final sin cuenta RQE: es lo único que necesitas mandarle.
  </Step>
  <Step title="Espera el webhook `domain.verified`">
    No poleas. RQE reintenta la verificación sola y avisa por webhook cuando el DNS propaga. Ver [Webhooks](/api-reference/webhooks#domainverified-domainfailed).
  </Step>
  <Step title="Opera en su nombre">
    Con la `api_key` del cliente, [envía](/api-reference/public-api), gestiona [contactos](/api-reference/leads) y lee actividad — todo aislado a ese proyecto.
  </Step>
</Steps>

## POST /v1/partner/projects

Crea un proyecto-cliente dentro de tu organización de partner. El `slug` y la `api_key` se generan automáticamente.

**El único campo obligatorio es `name`.** `domain` y `sender` son opcionales y nuevos: si los envías, el alta queda completa en esta misma llamada. Si no, el endpoint responde igual que siempre.

<Info>
  **Compatibilidad: si ya integraste el flujo anterior, no necesitas cambiar nada.** La llamada con solo `{ "name": "..." }` sigue siendo válida y su respuesta no cambió. Los campos nuevos se agregan, no reemplazan.
</Info>

### Request Body

| Campo          | Tipo   | Requerido | Descripción                                                                                     |
| -------------- | ------ | --------- | ----------------------------------------------------------------------------------------------- |
| `name`         | string | Sí        | Nombre del cliente (ej. `Phrasso`).                                                              |
| `external_key` | string | No        | Tu identificador interno del cliente (máx. 200 caracteres). Hace la llamada **idempotente**.     |
| `domain`       | string | No        | **Nuevo.** Dominio de envío del cliente (ej. `phrasso.com`). Va siempre junto con `sender`.      |
| `sender`       | object | No        | **Nuevo.** `{ "name": "Phrasso", "email": "hola@phrasso.com" }`. Va siempre junto con `domain`.  |
| `webhook_url`  | string | No        | URL HTTPS de webhooks del proyecto. Si se omite, hereda la de tu proyecto raíz.                  |
| `timezone`     | string | No        | Zona horaria IANA (ej. `America/Lima`).                                                          |
| `country`      | string | No        | Código de país del cliente.                                                                      |

<Warning>
  **`domain` y `sender` viajan juntos o no viajan.** SES no registra un dominio sin una dirección `From`, así que no hay forma de dar de alta uno sin el otro. Si mandas solo uno, la respuesta es `400` **antes de crear nada**: `SENDER_REQUIRED_FOR_DOMAIN` o `DOMAIN_REQUIRED_FOR_SENDER`. Y si el correo no termina en el dominio, `400 SENDER_DOMAIN_MISMATCH`.
</Warning>

### Ejemplo mínimo — solo el proyecto

El flujo de siempre, sin cambios. Crea el proyecto y devuelve su API key; el dominio y el remitente los configuras después con los endpoints de abajo.

<Tabs><Tab title="cURL">

```bash
curl -X POST https://api.reallyquickemails.com/v1/partner/projects \
  -H "Authorization: Bearer sk_partner_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Phrasso" }'
```

</Tab><Tab title="Python">

```python

    headers={"Authorization": "Bearer sk_partner_xxxxxxxxxxxx"},

print(resp.json())
```

**Respuesta** `201 Created`

```json
  "slug": "phrasso",
  "api_key": "sk_proj_xxxxxxxxxxxxxxxxxxxxxxxx"
}
```

Esa forma del objeto `sender` —con `id`, `sender_source`, `can_send` y `created_at`— es **la misma en los cuatro lugares** donde aparece un remitente: el alta, el alta de dominio, la creación de remitentes y el detalle del proyecto.

### El pack DNS

`domain.records` trae el pack completo, no solo DKIM. Se deriva entero en una sola llamada.

<Tip>
  **El cliente publica `fqdn`, no `name`.** Los registros que genera SES son **relativos** al dominio (`_amazonses`, `@`, `_dmarc`, `send`), mientras que los de reply y tracking son **absolutos**. `fqdn` es siempre el nombre listo para pegar en el DNS, sin pensar; `name` está para que coincida con lo que muestran los endpoints de [`/domains/*`](/api-reference/domains).
</Tip>

| Tipo    | `purpose`                             | Para qué                                                        |
| ------- | ------------------------------------- | ----------------------------------------------------------------- |
| TXT     | `ses_verification`                    | Prueba de propiedad del dominio.                                  |
| CNAME   | `dkim`                                | Firma DKIM del dominio del cliente. Son **3**.                    |
| TXT     | `spf`                                 | SPF en la raíz.                                                   |
| TXT     | `dmarc`                               | DMARC gestionado, en `p=none` para empezar a recibir reportes.    |
| MX, TXT | `return_path`                         | MAIL FROM propio en `send.`: rebotes y quejas alineados.          |
| CNAME   | `tracking`                            | Links de click en `links.`, con el dominio del cliente.           |
| TXT, MX | `reply_verification`, `reply_inbound` | Reply-To limpio en `reply.`, sin token.                           |

`status` por registro: `not_set`, `propagating`, `mismatch` o `verified`. El campo `priority` aparece solo en el MX de reply; el de `send` lleva la prioridad dentro de `value`. Detalle de cada registro en [Dominios](/api-reference/domains#registros-dns-generados).

<Note>
  **El nombre `records` es solo de los endpoints bajo `/v1/partner`.** Los de [`/domains/*`](/api-reference/domains), que se llaman con la API key del cliente, siguen devolviendo el array como `dns_records`. No cambió nada ahí.
</Note>

**Reply y tracking son best effort.** Si alguno falla, el dominio queda registrado igual y el motivo viaja en `warnings[]` — el alta no se cae por eso.

### Idempotencia

Con `external_key`, reintentar la llamada **devuelve el mismo proyecto** en vez de duplicarlo. Es el campo con el que amarras el cliente de tu sistema al proyecto RQE: úsalo siempre.

Si el `external_key` corresponde a un cliente **deshabilitado**, la respuesta es `409 PROJECT_DISABLED` con el `project_id` en el cuerpo, para que sepas cuál reactivar.

### Alta parcial

Solo aplica si enviaste `domain` y `sender`. Si el proyecto se crea pero el registro del dominio falla, la respuesta llega con `partial: true` y el detalle en `errors[]`. **El proyecto y su `api_key` son válidos**: reintenta el dominio con `POST /v1/partner/projects/{projectId}/domains`.

Cada entrada de `errors[]` y de `warnings[]` es `{ step, error_code, error }`. En `errors[]`, `step` solo toma el valor `domain`: el remitente se crea **dentro** del registro del dominio, así que no hay un paso suyo que pueda fallar por separado. En `warnings[]`, `step` toma `reply_domain`, `tracking_domain` o `verification_link` — los pasos best effort que no tumban el alta.

```json
{
  "project_id": "c22e3647-0e4b-4d71-99e2-651dbbac3eb2",
  "slug": "phrasso",
  "api_key": "sk_proj_xxxxxxxxxxxxxxxxxxxxxxxx",
  "partial": true,
  "domain": null,
  "sender": null,
  "errors": [
    { "step": "domain", "error_code": "DOMAIN_SENDER_CONFLICT", "error": "phrasso.com ya está asociado a otro remitente verificado." }
  ]
}
```

<Note>
  **Nunca descartamos un paso en silencio.** Si no ves `partial` ni `warnings` en la respuesta, todo salió bien.
</Note>

### El bloque `health`

Es **por proyecto**, no la forma de [`GET /domains/health`](/api-reference/domains#get-domainshealth): acá no hay `summary` ni `data`.

| Campo                   | Descripción                                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `status`                | `healthy` · `warning` · `critical`, para el cliente entero.                                    |
| `can_send`              | Si el cliente tiene al menos un dominio que puede enviar.                                      |
| `dkim_verified`         | Si el DKIM está verificado. **Se llama así, no `dkim`** — ese nombre es el de `by_domain[].auth`. |
| `domains_total`         | Dominios registrados en el proyecto.                                                           |
| `domains_authenticated` | Cuántos de ellos están autenticados. La brecha entre ambos es el trabajo pendiente.            |
| `sent`                  | Envíos en la ventana (`period_days`).                                                          |
| `hard_bounce_rate`      | Rebote duro del cliente, **ponderado por volumen** — no el promedio de los porcentajes por dominio. |
| `issues`                | Qué le falta, en texto accionable. Puedes reenviarlo tal cual a tu cliente.                    |
| `by_domain`             | La salud de siempre por dominio, con `auth: { ses, spf, dmarc, dkim }`.                        |

<Warning>
  **`can_send: true` con `status: critical` es el caso que más cuesta.** El correo sale con `200` y nada parece roto, pero va sin DKIM del dominio del cliente. Ver [Antes de enviar volumen](#antes-de-enviar-volumen).
</Warning>

## PATCH /v1/partner/projects/&#123;projectId&#125;

Actualiza los datos del proyecto-cliente. Solo se tocan los campos que envías.

### Request Body

| Campo         | Tipo   | Descripción                                            |
| ------------- | ------ | -------------------------------------------------------- |
| `name`        | string | Nuevo nombre del cliente. El `slug` **no** cambia.       |
| `webhook_url` | string | URL HTTPS de webhooks. Escribe también `inbound_webhook_url` con el mismo valor, igual que el alta. |
| `timezone`    | string | Zona horaria IANA.                                       |
| `country`     | string | Código de país.                                          |

Un `PATCH` sin ningún campo reconocido responde `400 EMPTY_PATCH`.

<Tabs><Tab title="cURL">

```bash
curl -X PATCH https://api.reallyquickemails.com/v1/partner/projects/c22e3647-0e4b-4d71-99e2-651dbbac3eb2 \
  -H "Authorization: Bearer sk_partner_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{ "webhook_url": "https://tuapp.com/hooks/rqe/v2", "country": "CL" }'
```

</Tab></Tabs>

**Respuesta** `200 OK` — el proyecto actualizado, envuelto en `project`.

El `slug`, en cambio, es estable de por vida: los links de tracking de los emails ya enviados dependen de él, y cambiar el `name` no lo mueve.
</Note>

## Dominios del cliente

Los mismos dominios que `/domains/*`, pero con **tu partner-key** y el `projectId` del cliente en la ruta: no necesitas tener a mano la `api_key` de cada uno.

### POST /v1/partner/projects/&#123;projectId&#125;/domains

Registra el dominio de envío del cliente, deriva el [pack DNS completo](#el-pack-dns) y crea el link público de verificación.

| Campo          | Tipo   | Requerido | Descripción                                                        |
| -------------- | ------ | --------- | -------------------------------------------------------------------- |
| `domain`       | string | Sí        | Dominio del cliente (ej. `phrasso.com`).                            |
| `sender`       | object | Sí        | `{ "name": "Phrasso", "email": "hola@phrasso.com" }`. El correo debe terminar en el dominio. |
| `external_key` | string | No        | Tu identificador interno del dominio.                                |

<Warning>
  **El remitente es obligatorio y va anidado en `sender`**, no como `sender_name` y `sender_email` sueltos. SES no registra un dominio sin una dirección `From`, así que no hay alta de dominio "pelada".
</Warning>

<Tabs><Tab title="cURL">

```bash
curl -X POST https://api.reallyquickemails.com/v1/partner/projects/c22e3647-0e4b-4d71-99e2-651dbbac3eb2/domains \
  -H "Authorization: Bearer sk_partner_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "domain": "phrasso.com",
    "sender": { "name": "Phrasso", "email": "hola@phrasso.com" }
  }'
```

</Tab></Tabs>

**Respuesta** `201 Created` — o `200 OK` con `reused: true` si el dominio ya estaba registrado. El pack sale al nivel de arriba, sin envolver.

```json

  "domain": "phrasso.com",

  "can_send": false,
  "reused": false,
  "verification_url": "https://app.reallyquickemails.com/verificar-dominio/9f1c2d3e-4a5b-4c6d-8e9f-0a1b2c3d4e5f",
  "reply_domain": { "domain": "reply.phrasso.com", "status": "pending" },
  "tracking_domain": { "domain": "links.phrasso.com", "status": "pending" },
  "records": [
    { "record_type": "TXT", "name": "_amazonses", "fqdn": "_amazonses.phrasso.com", "value": "abcdef1234567890abcdef1234567890", "purpose": "ses_verification", "status": "not_set", "ttl_hint": 300 }
  ],
  "sender": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "from_name": "Phrasso",
    "from_email": "hola@phrasso.com",
    "sender_source": "manual",
    "domain_authenticated": false,
    "email_verified": false,
    "can_send": false,
    "external_key": null,
    "created_at": "2026-07-22T16:00:00.000Z"
```

<Note>
  **El alta de dominio es idempotente.** Repetirla sobre un dominio ya registrado responde `200` con `reused: true` y sus registros existentes, en vez de fallar. Reintentar un alta que quedó a medias es seguro.

<Tip>
  **El `verification_url` es lo que le mandas al cliente final.** Es una página pública que muestra sus registros con botón de copiar y un botón de verificar. No expone nada del proyecto: solo el dominio y sus registros, que son públicos por definición. No hace falta que tu cliente tenga cuenta RQE.
</Tip>

### POST /v1/partner/projects/&#123;projectId&#125;/senders

Crea un remitente. **Por defecto exige un dominio verificado**: es la regla que evita que un cliente nazca enviando sin autenticar.

| Campo                   | Tipo    | Requerido | Descripción                                                                        |
| ----------------------- | ------- | --------- | ------------------------------------------------------------------------------------ |
| `name`                  | string  | Sí        | Nombre visible del remitente.                                                        |
| `email`                 | string  | Sí        | Dirección del remitente.                                                             |
| `external_key`          | string  | No        | Tu identificador interno del remitente.                                              |
| `allow_unauthenticated` | boolean | No        | `true` para permitir la verificación por correo (magic link) cuando el dominio no está verificado. Default `false`. |

`name` y `email` se aceptan **sueltos en el cuerpo o anidados en `sender`**: las dos formas funcionan.

<Tabs><Tab title="cURL">

```bash
curl -X POST https://api.reallyquickemails.com/v1/partner/projects/c22e3647-0e4b-4d71-99e2-651dbbac3eb2/senders \
  -H "Authorization: Bearer sk_partner_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Phrasso", "email": "hola@phrasso.com" }'
```

</Tab></Tabs>

**Respuesta** `201 Created`

```json
{
  "sender": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "from_name": "Phrasso",
    "from_email": "hola@phrasso.com",
    "sender_source": "manual",
    "domain_authenticated": true,
    "email_verified": true,
    "can_send": true,
    "external_key": null,
    "created_at": "2026-07-22T16:00:00.000Z"
  },
  "path": "domain",
  "domain": "phrasso.com",
  "domain_verification_status": "verified"
}
```

`path` dice por dónde salió el remitente: `domain` (sobre el dominio verificado) o `magic_link`. En el camino del magic link la respuesta suma un `warning` avisando que ese remitente no tiene DKIM.

Si el dominio del correo no está verificado y **no** enviaste el flag:

**Respuesta** `422 Unprocessable Entity`

```json
{
  "error": "El dominio phrasso.com no está verificado. Registra el dominio o envía allow_unauthenticated: true para verificar el correo por magic link.",
  "code": "DOMAIN_NOT_VERIFIED",
  "error_code": "DOMAIN_NOT_VERIFIED",
  "domain": "phrasso.com",
  "verification_status": "pending"
}
```

`verification_status` viene en `null` cuando el dominio ni siquiera está registrado.

Con `allow_unauthenticated: true` se envía un correo de verificación a la dirección y el remitente nace con `sender_source: "magic_link"`, `domain_authenticated: false` y `email_verified: false` hasta que el destinatario hace clic.

<Note>
  **La exigencia del dominio verificado es solo de este endpoint.** [`POST /domains/verify-email`](/api-reference/domains#post-domainsverify-email) y el resto de `/domains/*`, que se llaman con la API key del cliente, funcionan igual que siempre: no piden el flag ni devuelven `DOMAIN_NOT_VERIFIED`.
</Note>

<Warning>
  **El magic link es la excepción, no el atajo.** Verifica la casilla, no el dominio: SES firma con `d=amazonses.com`, así que el DKIM nunca queda alineado con el dominio del cliente. Úsalo solo cuando el cliente no controla su DNS, y nunca para volumen. Ver [Antes de enviar volumen](#antes-de-enviar-volumen).
</Warning>

## Antes de enviar volumen

**Registra el dominio del cliente antes del primer envío grande.** No es una recomendación de higiene: es la diferencia entre llegar a la bandeja y no llegar.

Un remitente verificado solo por correo (magic link) sale firmado con el dominio compartido de la plataforma. El resultado, medido en clientes reales:

- **Microsoft rechaza con `5.7.515`.** Ve `SPF=Pass, DKIM=Pass, DMARC=Fail` porque nada está alineado con el dominio del `From`, y a remitentes con volumen los corta ahí mismo.
- **Gmail responde `550-5.7.1 "likely unsolicited mail"`.** Sin DKIM propio, la reputación del cliente se mezcla con la de todos los demás que envían sin autenticar.
- **No hay reply domain ni tracking domain.** Ambos cuelgan del dominio verificado.

Nada de esto aparece como error en tu integración: la API responde `200`, el correo "se envía" y el problema se ve semanas después en la tasa de rebote.

<Steps>
  <Step title="Crea el cliente con su dominio">
    `POST /v1/partner/projects` con `domain` y `sender`. El pack DNS viene en la respuesta.
  </Step>
  <Step title="Reenvía el verification_url">
    Es una página pública con los registros y un botón de verificar. Es lo único que tu cliente final necesita abrir, sin cuenta RQE. Si su proveedor de DNS soporta [Domain Connect](/api-reference/domains#get-domainsdomaindomain-connect), la publicación es de un clic.
  </Step>
  <Step title="Espera domain.verified">
    Llega por webhook. Recién ahí habilita el envío de volumen de ese cliente.
  </Step>
  <Step title="Vigila la salud">
    `GET /v1/partner/projects/{projectId}` trae `health`. Un cliente en `critical` con `can_send: true` está quemando reputación en silencio.
  </Step>
</Steps>

<Warning>
  **Mira el hard bounce, no el total de rebotes.** Los proveedores calculan el umbral de suspensión (~5%) sobre los rebotes **permanentes**; los temporales no cuentan. Un dominio puede mostrar 12% de rebote total y estar por debajo del 1% de hard bounce.
</Warning>

## Errores

Todas las respuestas de error tienen la misma forma:

```json
{
  "error": "Mensaje legible.",
  "code": "MAX_PROJECTS_REACHED",
  "error_code": "MAX_PROJECTS_REACHED"
}
```

`code` y `error_code` llevan **siempre el mismo valor**. `error_code` es el canónico; `code` está por compatibilidad con integraciones existentes. Algunos errores suman campos extra al cuerpo, planos, para que no tengas que parsear el texto.

### Códigos de error

| Código | `error_code`                 | Descripción                                                                     |
| ------ | ---------------------------- | --------------------------------------------------------------------------------- |
| `400`  | `MISSING_NAME`               | Falta `name` al crear el proyecto.                                                |
| `400`  | `INVALID_EXTERNAL_KEY`       | `external_key` supera los 200 caracteres.                                         |
| `400`  | `INVALID_WEBHOOK_URL`        | `webhook_url` no es una URL válida o no usa HTTPS.                                |
| `400`  | `INVALID_TIMEZONE`           | `timezone` no es una zona horaria IANA válida.                                    |
| `400`  | `INVALID_COUNTRY`            | `country` no es un código de país válido.                                         |
| `400`  | `INVALID_PROJECT_ID`         | El `projectId` de la ruta no es un UUID.                                          |
| `400`  | `EMPTY_PATCH`                | El `PATCH` no trae ningún campo reconocido.                                       |
| `400`  | `MISSING_DOMAIN`             | Falta `domain` al registrar un dominio.                                           |
| `400`  | `INVALID_DOMAIN`             | El dominio tiene formato inválido.                                                |
| `400`  | `INVALID_SENDER`             | `sender` no es un objeto con `name` y `email`.                                    |
| `400`  | `MISSING_SENDER_NAME`        | Falta el nombre del remitente.                                                    |
| `400`  | `INVALID_SENDER_EMAIL`       | La dirección del remitente tiene formato inválido.                                |
| `400`  | `SENDER_REQUIRED_FOR_DOMAIN` | Mandaste `domain` sin `sender`. Van juntos.                                       |
| `400`  | `DOMAIN_REQUIRED_FOR_SENDER` | Mandaste `sender` sin `domain`. Van juntos.                                       |
| `400`  | `SENDER_DOMAIN_MISMATCH`     | El correo del remitente no termina en el dominio que registras.                   |
| `401`  | —                            | Partner-key ausente o inválida.                                                   |
| `404`  | `NOT_FOUND`                  | El proyecto no existe en tu organización. Un tenant ajeno responde igual.         |
| `404`  | `DOMAIN_NOT_FOUND`           | El dominio no existe en ese proyecto.                                             |
| `409`  | `MAX_PROJECTS_REACHED`       | Alcanzaste tu cupo. Trae `max_projects` y `active_projects` en el cuerpo.         |
| `409`  | `PROJECT_DISABLED`           | El `external_key` del alta corresponde a un cliente deshabilitado. Trae `project_id`. |
| `409`  | `DOMAIN_SENDER_CONFLICT`     | El dominio ya está asociado a otro remitente verificado.                          |
| `422`  | `DOMAIN_NOT_VERIFIED`        | El remitente exige dominio verificado. Trae `domain` y `verification_status`.     |
| `500`  | `NO_OWNER`                   | Tu organización de partner no tiene owner.                                        |
| `500`  | `CREATE_FAILED`              | Error interno al crear el proyecto.                                               |

<Note>
  **`PROJECT_DISABLED` sale únicamente en el alta**, cuando reutilizas el `external_key` de un cliente deshabilitado. Trae el `project_id` para que sepas a cuál llamar `/reactivate`. Un `PATCH` sobre un cliente deshabilitado **sí funciona**, a propósito: así puedes dejarle bien el webhook antes de reactivarlo.
</Note>
